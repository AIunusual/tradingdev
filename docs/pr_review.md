# PR 初審回覆

## 第一次審查

用繁體中文寫給要修正這份 PR 的作者。優先指出這次變更造成、會影響使用者或下游呼叫端的問題。
每項發現對應一個可獨立處理的問題，指出檔案與程式位置、觸發條件、預期與實際行為，以及具體影響。
附上從差異可核對的證據，或一個能驗證修正的情境。若結論取決於尚未取得的資料，說明缺哪項證據。
只有實際執行過的檢查才能寫成已驗證。

## PR 更新後

對照前次發現與目前的 PR 差異，逐項核對。仍存在的問題沿用原標題與描述，更新程式位置；
新引入或再次出現的問題指出本次觸發條件。只修了一部分時，說明仍會失敗的情境。
只有新版本的程式或驗證結果足以排除原情境，才回報修正；證據不足的項目保留待確認。

在 **Files changed → Conversations** 核對未解決的討論串，包括行號已過時的項目。
每個可定位的問題使用獨立的 GitHub review thread。作者在原討論串回覆修正 commit、驗證結果，
或說明保留現行行為的理由，審閱者核對後再選 **Resolve conversation**。
新 commit、過時的行號與新版摘要漏列舊問題都不足以結案。任何只有一般留言或摘要、沒有獨立
thread 的問題，作者在推送修正前於 PR 描述逐項建立待辦，記下受查 commit、問題、待驗證情境
及原留言連結。後續修正回到同一項補上 commit 與驗證結果，審閱者核對後再勾選。
