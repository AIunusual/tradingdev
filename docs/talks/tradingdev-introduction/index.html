開場先介紹現有工具，再說明 TradingDev 要完成的整合工作。讓聽眾先理解選擇這個專案的理由，再看一個交易想法如何變成可檢查的實驗。 初稿專案事實基準：d57da5c20aa7dc578dabef92bbf14d796df8adb6；執行確認與報告交付流程依對應頁面所列的新版本更新。外部資料查核：2026-10-25 至 2026-10-26。 來源：https://github.com/Kuan-Lun/tradingdev/blob/d57da5c20aa7dc578dabef92bbf14d796df8adb6/README.md

回測是用歷史行情模擬交易規則。現有工具已能完成許多計算與研究工作，TradingDev 也沿用其中的成熟套件。 Freqtrade 是含回測、最佳化及交易功能的應用。cloudQuant/backtrader-mcp、bcosm 也支援自訂策略，後段逐一比較。QuantConnect 平台已涵蓋完整研究流程，不能把它描述成只有回測引擎。

每列描述特定路線的整合責任，不能推論整個市場都沒有這些功能。個人 Python 環境以 VBT PRO 的持續 kernel 為例；模板型工具以所查 MaverickMCP 的自然語言模板路徑為例。 QuantConnect 已提供策略建立、回測與結果分析。其取捨在於採用平台的策略及專案模型，或投入自行整合的工作。其他開源 MCP 也有相近流程，詳細差異留在後段比較。

後端可理解為真正接收工具請求、執行計算和保存資料的程式服務。使用者不必自己把一次次實驗的程式、設定和結果拼回來。 TradingDev 不內建對話模型。跨設備部署需要安排連線與存取控制，現有主機分工不代表已提供多租戶或叢集排程。

自主性是整合者願意維護研究服務時的產品選擇，並非只有 TradingDev 能外接模型或自架。完整平台也有自管與外部模型路線，後段比較採用方式。 工程經驗回饋可由外部開發助手接入，但目前沒有完成自動抽象、修改與整合。先用現有研究紀錄建立可驗證的改進案例。

這是完整閱讀版，不限定演講時間。先講現有選擇與專案定位，再選擇研究流程及相關的詳細比較案例，其餘內容保留給網站閱讀。

研究不是泛稱投資分析。此處具體指策略程式的建立、檢查、歷史回測、參數實驗、時序驗證與結果查詢。 來源：專案 README、ARCHITECTURE.md。

讓一般聽眾看到，口頭想法和可執行策略之間還有許多選擇。助手的任務之一是協助釐清，而不是替使用者悄悄決定。

可以用「歷史實驗」解釋回測。資料、費用、成交假設和選取期間都會影響答案，不把漂亮結果視為未來保證。

讀作 MCP，不是 MPC。TradingDev 不提供對話模型，搭配支援 MCP 的客戶端使用。研究的判斷和工具的計算各有責任。 來源：https://github.com/Kuan-Lun/tradingdev/blob/d57da5c20aa7dc578dabef92bbf14d796df8adb6/ARCHITECTURE.md

新策略會保存版本，通過驗證及 dry-run 後才取得執行資格；其中的訊號檢查使用固定合成資料，並非歷史回測。準備確認單時只做離線程式與設定檢查，以及適用的合成訊號檢查。單次準備的內建策略不在此時執行訊號；固定參數比較則對每組候選（包含內建策略）執行 80 與 240 根合成 K 棒的訊號檢查。確認前不取得真實行情、不訓練模型、不執行歷史回測；行情、訓練及績效須同意後才開始驗證。 來源：README「完成第一次回測」、docs/strategy_contract.md。

這是與僅選擇固定模板的工具相比可具體展示的差異，但不是所有 MCP 專案都只支援模板。cloudQuant/backtrader-mcp 和 bcosm 也支援自訂策略，後面分別比較。

確認前不取得真實行情、不訓練模型、不執行歷史回測；自建策略適用的訊號檢查只用固定合成資料。單次準備的內建策略只檢查設定、執行模式與參數；固定比較的每組候選則都要通過 80 與 240 根合成 K 棒的訊號檢查，包含內建策略。一到八組普通回測的固定候選可共用一份確認單，使用者批准整組後才執行；這不包含需要訓練或 walk-forward 的多組比較，也不會自動擴大搜尋。修改候選或設定後要準備新的計畫並重新確認。後端依賴助手如實轉交使用者決定，不能獨立驗證決定的人類來源。這項限制留在講者稿，操作細節以 README 為準。 來源：README「完成第一次回測」、docs/run_artifacts.md 的 execution plans。

結果主要供 LLM 查詢和分析。詳細交易、帳戶序列與執行紀錄可分頁查詢；不存在的舊紀錄不能靠助手猜測重建。 來源：src/tradingdev/mcp/tools/history.py、runs.py 與 mcp/prompts.py。

strategy/revision、plan、job、run 的用途不同。job 用於進度與取消，run 用於已保存結果；現有 ID 是追蹤基礎，不等於已綁定使用者擁有權。固定比較以同一份行情快照獨立執行各組普通回測，使用各自資金與策略實例，不合併成一個投資組合。完整比較報告依父工作選取所有候選，包含失敗、取消及未執行的原因；成功結果可點選查看明細。 來源：ARCHITECTURE.md 的 strategy identity 與 run artifacts。

避免用「自動找到最佳策略」形容參數最佳化。工具在指定候選、指標與訓練期間中選擇結果，再用保留區間檢驗。 來源：README「研究與比較參數」、ARCHITECTURE.md 的 optimization。

signal 使用 VectorBT，包含初始資金。volume 從零累計 P&L，沒有初始資金，不能當作本金報酬率；名目規模可由 size_weight 調整。volume 也不是市場深度或成交量限制撮合模型。 來源：https://github.com/Kuan-Lun/tradingdev/blob/d57da5c20aa7dc578dabef92bbf14d796df8adb6/src/tradingdev/domain/backtest/result.py 其他引擎：https://vectorbt.dev/api/portfolio/base/#simulation-modes 、 https://www.quantconnect.com/docs/v2/writing-algorithms/trading-and-orders/position-sizing

對話仍是查詢、解讀與修正策略的主要入口，使用者不必閱讀圖表。完成回測並解讀績效、風險時，助手預設交付標準報告連結、對應結果及查看明細的方法；使用者可明確選擇只要摘要。執行後報告與執行前確認單分開。保存紀錄不等於保存完整軟體環境，不能保證跨環境完全重現。 來源：https://github.com/Kuan-Lun/tradingdev/blob/7298a4d8cf0769c0db7f92f0df46e2e739c8e470/README.md#交易紀錄與-html-報告 及同版本 docs/run_artifacts.md。

以筆電與公司主機說明。遠端放置後端是架構可行性；目前 CLI 的 HTTP 預設綁定 localhost，跨設備需轉送。不能宣稱已有多節點叢集或大型租戶平台。 來源：README 的 Streamable HTTP 設定與限制。

這是定位重點，但不能說只有 TradingDev 能外接 LLM 或自架。差異在於可以直接維護自己的研究服務實作，以及願意承擔哪些整合責任。 來源：ARCHITECTURE.md；QC MCP 與 Private Cloud 文件供比較。

對話 LLM 在公司的產品入口，token 使用量也由該層計量。後端可以配合公司的既有產品流程，公開多人產品仍需另行整合。 真正收費上線時另核實依賴及行情授權。這項工作不屬本次簡報實作。

目前可先在可信環境採獨立部署；同一 server 的 workspace 不能當作現成多租戶隔離。QuantConnect Private Cloud 也可保留公司資料與運算，不把私有部署說成獨有。

這些是依現有能力提出的使用情境，不是假裝已完成的客戶案例。教學重點是如何檢查假說，不是比較誰的回測收益最高。

ML 不作為獨有賣點。TradingDev MCP 模型目前包含 XGBoost、LightGBM、CatBoost 方向模型；QC 支援更多常見框架。模型種類不代表較泛用。 TradingDev 實際使用 VectorBT、TA-Lib、QuantStats 等套件；沒有把 Freqtrade 整合為依賴。 來源：pyproject.toml、src/tradingdev/domain/ml/models/registry.py；https://www.quantconnect.com/docs/v2/writing-algorithms/machine-learning/popular-libraries/pytorch

這是為了說明的分類，不是嚴格互斥的產品分類。Freqtrade 是完整交易應用，比單純函式庫更高一層；LEAN 引擎與 QuantConnect 平台也要分開。

重點是基礎功能有被整合，不把底層套件當作功能不足的對手。Freqtrade 本身已提供很多產品功能，不能說使用它一定要從頭自行組裝。 原版 Backtrader 主線更新停在 2023 年，社群分支持續修正。維護情況依分支而異，不用 issue 數量推論品質。 來源：https://github.com/cloudQuant/backtrader/blob/development/CHANGELOG.md 、 https://github.com/backtrader2/backtrader/issues/98

不能說 VectorBT PRO MCP 只能查文件，或不能開發策略。它也有可由助手讀取的研究 skills。其公開設計不能直接當作完整多人後端，但每人獨立環境是可能的。

MaverickMCP 有自己的優勢，包括模板便利性、Monte Carlo 與 ensemble 工具。不要把自然語言解析成模板說成不能做任何策略研究。 所查 MCP 介面未見等價的新策略原始碼保存、revision 驗證及持久背景 job 生命週期。這是介面範圍比較，不是斷言開發者不能擴充原始碼。

cloudQuant 與 QuantConnect 是不同專案。它有持久工作、取消及日誌，與 TradingDev 的部分功能相近。移入策略時要依各自格式改寫，對話追問能力則取決於結果查詢的範圍。 獨立的 backtrader-skills、backtrader-agent 另有流程與有限 sweep 經驗保存，不能自動視為主 MCP repository 已整合的功能。

bcosm 的驗證工具有 verdict/reasons，流程範例放在 examples/agent_workflow_demo.py。未註冊 prompts 不能簡化成完全沒有引導。 save_run 接收呼叫端提交的 metrics/code/params，與 TradingDev 固定實際執行設定、保存產物的流程不同。

LEAN engine 為 Apache-2.0，可自行建置；官方 CLI/Local Platform 與 Private Cloud 有各自方案條件。不要把官方 remote MCP 的付費 Agent Node 要求套到所有自行使用 LEAN 的情境。

QC 已有新策略建立、編譯、回測、最佳化及結果診斷，不能宣稱 TradingDev 的完整研究流程對 QC 也是獨有。 本頁表達工作方式與維護責任。要主張某個情境更省事或成本更低，仍需具體部署評估。
